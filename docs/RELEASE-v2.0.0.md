# v2.0.0 升级和操作说明

## 升级与回退

1. 关闭旧版本程序，将数据目录、图片目录和配置文件备份到外部存储。
2. 替换 EXE，保留数据和配置。首次启动先备份旧数据库到 `data/backups/pre-v2-*.db`，再事务化迁移；无效日期或损坏关联会阻止启动，并指出记录编号。
3. 每条旧进销记录转换为一张单据，保留旧 ID 映射、款号和尺码快照。库存按商品与尺码 ID 计算，空尺码归入“未指定”。
4. 历史毛利按商品尺码移动加权重建。同日旧记录没有可靠业务先后时进货优先，其余按创建时间、稳定编号排序。升级后核对暂估、待核算及待重算提示。
5. 首次账号登录必须修改密码；旧账号仍使用 `admin123` 时也须改密。密码至少 8 位，改密撤销全部会话；旧版令牌失效。
6. 回退须停机，恢复旧 EXE 以及升级前数据库和图片。不要使用旧 EXE 继续操作 v2 数据，否则无法反映新流水。

`DATA_DIR` / `DB_PATH` 配置数据库，`STATIC_DIR` 配置图片。EXE 所在目录不可写时使用用户数据目录，路径规则见 `backend/app/paths.py`。默认不生成演示商品及虚构厂家，体验时显式设置 `SEED_DEMO=1`。

## 开单、退货和盘点

进货及销售支持一单多商品，整单保存或整单失败。网络超时后未改变内容再次提交会复用幂等键；不要刷新页面后盲目重开，应先查询原单。

单据中心按类型、状态、日期、款号、分类、厂家、尺码筛选。有效单据不能直接编辑或删除；更正时填写原因作废，并复制重开。作废生成反向库存流水；原单有关联退货时须先作废退货单。

从有效进货或销售原单详情点击“关联原单退货”，移除不退的明细并修改数量，累计退货不能超过原数量。销售退货按原销售成本回库，采购退货按原采购价出库。本版不包含专用换货流程、供应商结算和 Excel 历史导入。

盘点输入实盘数量并填写原因；所选库存版本变化时须刷新核对。库存调整支持调增、调减，无历史成本的调增必须输入单位成本。库存累计入库、出库包含退货、调整和作废反向流水。

## 成本口径

价格采用整数分，单位成本采用百万分之一元定点数，十进制四舍五入。销售保存成本快照，未来普通进货不会自动改变历史毛利。

继续允许负库存销售：按最近有效成本暂估；从未有过成本时标记待核算。补货或历史更正后，到单据中心预览并确认成本重算。补货按先进缺口分摊至负库存销售，缺口完全覆盖后解除暂估；预览后有新业务则必须重新预览。

报表进销金额计入退货净额，毛利不包含盘盈盘亏损益。存在未知销售成本时显示待核算，不按零成本计算利润；暂估和待重算均显示提示。

## 完整备份与网页恢复

设置中下载完整备份，包含一致性 SQLite 快照、商品图片及 SHA-256 清单，不包含本机配置密钥或配置密码。备份期间与业务写入串行；运行中不要仅复制 `.db` 文件。Excel 不能代替完整备份。

恢复操作：上传 ZIP → 校验并核对版本、时间、文件数 → 确认并进入维护模式 → 关闭并重新启动程序。最大压缩包 256MB、展开 512MB，拒绝非法路径、重复文件、校验失败、损坏数据库及不支持的版本。

确认前保留恢复前完整副本到 `data/backups/`。重启时先恢复再开放接口；恢复失败或中断后回滚并保持维护状态，核对后可在设置取消维护。成功恢复会撤销全部会话，使用备份中的账号密码重新登录；不会替换本机配置密钥。

## 验证与发布

后端：`python -m pip install -r backend/requirements-test.txt`，`python -m pytest backend/tests -q`。
前端：在 `frontend` 执行 `npm ci`、`npm test`、`npm run build`。

常规 CI 在 Linux、Windows 执行回归和前端构建。推送 `v*` 标签后，Windows 构建先跑测试，再打包并启动实际 EXE 检查迁移、登录和页面。Artifact 保留 30 天。真实手机扫码、系统防火墙及 Windows 交互仍需真机验收。本版不包含代码签名、自动更新或 HTTPS 配置。
