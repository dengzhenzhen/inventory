# 改进事项备忘

记录日期：2026-10-22。v2.0.0 已实施以下业务与基础改进，规则见 [升级说明](RELEASE-v2.0.0.md)。发布验证结果在交付时报告。

## 优先修复

- 库存使用稳定的 product_id + size_id 聚合，避免款号、尺码改名拆分库存。隔离验证：改款号后原有 19 件库存留在旧款号，新款号显示 0。
- 明确成本核算规则，避免未来进货改变历史毛利。隔离验证：新增二月份进货后，一月份销售估算成本从 10 变为 15。
- 401 时同步清理 Pinia 和 localStorage，避免路由守卫阻止进入登录页；区分登录失败和登录过期。
- 按本地日期生成默认单据日期，避免北京时间凌晨使用 UTC 前一天日期。
- 商品列表分页、选款远程搜索、扫码按款号查询，消除只加载前 500 条造成的漏选、误报及旧售价残留。

## 基础能力

- 正式运行使用独立 JWT 密钥、首次修改默认密码，并支持改密或退出后撤销旧凭证。
- 区分演示与正式数据初始化，源码运行默认演示数据需明确提示。
- 加强空白字符串、日期、非负零售价、分页、批量条数及字符串长度校验。
- 金额采用整数分或明确的十进制精度，定义成本精度和舍入规则。
- 提供一致性备份、图片打包、恢复校验，并明确停机与运行中备份方式。
- 引入数据库版本化迁移、升级前备份及旧数据升级验证。
- 增加关键业务回归测试及常规 CI：库存身份、批量回滚、历史成本、登录过期、日期边界。

## 后续产品及性能

- 盘点、退货、调整流水；单据作废或冲正及操作审计。
- 一单多件、提交幂等，避免重试重复出库。
- 导出复用当前列表筛选条件。
- 库存和报表在数据库侧聚合、分页，预加载关联数据，减少逐款查询。
- 前端组件和图标按需引入，减少首屏资源。

## 当前讨论

手机通过 HTTP + 局域网 IP 访问时，浏览器不允许实时摄像头 API。正在比较本地受信 HTTPS、免费域名证书、拍照识别等方案，尚未实施，本版明确不包含 HTTPS。
